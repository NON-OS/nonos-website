This page is for a contributor who wants to change the power service. It covers where the source lives,
which folder owns which behaviour, the exact steps to add an operation, how to build and sign the capsule,
and the code standards a change has to meet. For what the capsule does and how it is put together, read the
[README](/docs/userland/power/) and the [operations](/docs/userland/power/operations/) page.

## Where the source lives

The capsule is at `userland/capsule_power/`. It is a `no_std`/`no_main` IPC server: `_start` initializes
the heap and hands control to `server::run`, which loops forever on the service port
([`src/main.rs:29`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/main.rs#L29)). The three top-level modules are declared there ([`src/main.rs:22`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/main.rs#L22)).

## Module map

| Folder | Owns | Touch it when |
|--------|------|---------------|
| `src/protocol/` | the wire format: header, parse, encode, opcodes, error codes | you change the frame layout or add an opcode or status |
| `src/server/` | the request loop and the per-op handlers | you change how requests are served or what an op does |
| `src/state/` | the two request timestamps | you change what the capsule records across the process lifetime |

Inside `src/server/`, `runner.rs` is the loop, `respond.rs` builds the header-plus-status reply, and
`handlers/` holds one file per operation plus `router.rs`, which parses the frame and dispatches on the
opcode ([`src/server/handlers/router.rs:22`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/router.rs#L22)).

## Adding an operation

There are three edits, and the dispatch wiring is the load-bearing one.

1. Add the opcode constant to [`src/protocol/ops.rs:17`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/protocol/ops.rs#L17), following the existing `u16` values, and re-export
   it from [`src/protocol/mod.rs:27`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/protocol/mod.rs#L27).
2. Write the handler as one file under `src/server/handlers/`. A handler that needs the shared state
   exposes `pub fn run(state: &mut PowerState, out: &mut [u8], req: &Request) -> usize` and builds its
   reply through `respond::status`, returning the reply length, the way `reboot.rs` and `shutdown.rs` do
   ([`src/server/handlers/reboot.rs:23`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/reboot.rs#L23)). A stateless handler takes `(out, req)` instead, like
   `health.rs` ([`src/server/handlers/health.rs:20`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/health.rs#L20)).
3. Re-export the handler from [`src/server/handlers/mod.rs:17`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/mod.rs#L17) and add a match arm keyed on the new opcode
   in [`src/server/handlers/router.rs:27`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/router.rs#L27).

If the operation needs a new privileged verb from the kernel, that is a separate change on the kernel side:
a new `SyscallNumber` and a router arm under `src/syscall/dispatch/router/admin/`, gated in the cap table
at [`src/syscall/contract/cap_table/admin.rs:24`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/syscall/contract/cap_table/admin.rs#L24). Do not widen the capsule mask to reach a device directly;
the capsule holds Admin and nothing else on purpose (see the [README](/docs/userland/power/) identity table).

## Build, sign, verify

The per-slug make targets are generated by the rule template in `nonos-mk/capsule.mk:156` and instantiated
because the Makefile includes this capsule's `Capsule.mk` (`Makefile:683`):

```
  make nonos-mk-power                build the capsule ELF
  make nonos-mk-power-sign           produce the id cert, manifest, and attestation trailer
  make nonos-mk-power-verify         verify the signed artifacts against the trust anchor
  make nonos-mk-check-power-keys     check the per-capsule signing keys exist
```

There is no `nonos-mk-power-prod` target. Unlike a spawned desktop app such as the
[terminal](/docs/userland/terminal/), the power capsule has no dedicated production-image profile, because it
is not part of a spawned desktop fleet. It is pulled into the image through the shared artifact and verify
sets instead (`Makefile:731`, `Makefile:882`, `nonos-mk/capsule.mk:132`).

## Code standards

- `cargo fmt` and a clean `cargo clippy`.
- No panics, `unwrap`, or `expect` in capsule code. Every handler returns a status word, never a panic;
  parse failures come back as a negative status, not an abort ([`src/protocol/decode.rs:20`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/protocol/decode.rs#L20)).
- Modular files, one unit per file, with `mod.rs` used only for re-exports
  ([`src/protocol/mod.rs:17`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/protocol/mod.rs#L17), [`src/server/handlers/mod.rs:17`](https://github.com/NON-OS/nonos-micro-kernel/blob/main/src/server/handlers/mod.rs#L17)).
- The AGPL header at the top of every source file, matching the header on every existing module.

## Source map

```
  userland/capsule_power/src/main.rs             _start -> heap init -> server::run
  userland/capsule_power/src/protocol/           header, decode, encode, ops, errno, mod
  userland/capsule_power/src/server/             runner, respond, handlers (router + per-op)
  userland/capsule_power/src/state/mod.rs        the two request timestamps
  userland/capsule_power/Capsule.mk              slug, ports, 0x219 mask, declared kernel mirror
  nonos-mk/capsule.mk                            the generated nonos-mk-power[-sign|-verify] targets
  src/syscall/dispatch/router/admin/             where a new privileged verb would land
  src/syscall/contract/cap_table/admin.rs        the Admin gate a new admin syscall must join
```

Every reference above is verified against those trees.
