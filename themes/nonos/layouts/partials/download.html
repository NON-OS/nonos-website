Confirm you booted what we published

Do not skip this. The whole point of NØNOS is that you verify instead of trust. Two checks take ten seconds; the deeper ones prove the entire trust chain from a clean checkout.

1

Check the hash

Confirm the bytes you downloaded match the published checksums. Either algorithm is sufficient; both are provided.

verify · hash
$ b3sum -c BLAKE3SUMS
nonos-1.0.img: OK
$ sha256sum -c SHA256SUMS
nonos-1.0.img: OK

Every line must report OK. A mismatch means the download is corrupt or tampered. Do not boot it.

2

Verify the trust chain

With the kernel checked out, decode and verify every signed capsule against the baked trust anchor, the same check the running kernel performs.

verify · trust-chain
$ cargo run -p nonos-verify -- trust-chain
anchor: ed25519 + ml-dsa-65 ok
capsules: 14/14 verified ok

Confirms the hybrid Ed25519 and ML-DSA-65 signatures on the kernel and every capsule manifest resolve to the published anchor.

3

Reproduce the build

Rebuild from a clean worktree and compare hashes. If your build matches ours, the image is exactly the source, with nothing added.

verify · reproducible
$ cargo run -p nonos-verify -- reproducible
build A == build B ok
image == source ok

A reproducible build lets you trust the binary without trusting us. The image is the source, byte for byte.

What gates the boot

Downloading is the easy part. Here is what has to pass before a single instruction of your download runs, and why an old or altered image cannot slip through.

  1. i

    Signed kernel

    The bootloader authenticates the kernel's hybrid signature: Ed25519 for speed, ML-DSA-65 for post-quantum strength. The signed message is blake3(kernel) || rollback_index, so the hash and the version are bound together and cannot be separated.

    Signing and MAC →
  2. ii

    Anti-rollback

    The rollback index is enforced against a TPM monotonic counter that only moves forward. Once a newer kernel has booted, the floor rises for good. Re-flashing yesterday's vulnerable image to reopen yesterday's hole fails: the signature is valid, the index is not, and it does not boot.

    Attestation →
  3. iii

    Capsule attestation

    At spawn, the kernel's transparent STARK gate verifies each capsule's proof. It binds the capsule's BLAKE3 hash, its capability mask, and the policy epoch, and checks membership in the enrolled policy before the capsule runs. No trusted setup, nothing to leak.

    The proof system →
download→ hash matches→ kernel signature→ index ≥ TPM floor→ measured launch→ capsule attestation→ runs
